# Работа агента в проекте

Проект исследует минимальное машинное сознание в терминологии работ из `Articles/Core`: сравниваются дискретный автомат и RL в задаче навигации с внутренними ресурсами. Общение и содержательная документация — на русском; идентификаторы кода можно писать на английском.

Идеи объясняй через восприятие, внутренние показатели, аппарат принятия решений, действия и память клеток. Для расстояния по разрешённой дороге используй «длина пути», а не «стоимость». В пилоте D-0008 длина каждого разрешённого хода равна 1. Это рабочий выбор для диагностических уровней. Технический термин вводи с пояснением, когда он действительно нужен.

## Где брать контекст

- При возобновлении незнакомой работы используй [текущее состояние](docs/status.md) и [карту документации](docs/README.md). Для небольшой локальной правки достаточно относящихся к ней материалов.
- Требования и границы задачи: [project.md](docs/project.md). Нерешённые вопросы: [questions.md](docs/questions.md).
- Изменение устройства системы: [architecture.md](docs/architecture.md) и связанные [решения](docs/decisions/README.md).
- Литература: [Articles/README.md](Articles/README.md), затем нужный конспект. Не перечитывай все PDF для каждой задачи.
- Эксперименты: [протокол](docs/experiments/README.md). Длительная реализация: [roadmap.md](docs/roadmap.md) и относящийся к задаче план из [tasks](docs/tasks/README.md).
- Порядок обновления документов и команды: [workflow.md](docs/workflow.md).

## Ограничения, которые легко потерять

- Оба исследуемых агента имеют одинаковый информационный интерфейс. Внешнее наблюдение — 3×3, физических направлений движения — восемь.
- Пространственная память ограничена типами клеток и, возможно, числом посещений. Не добавляй в неё даты, историю переходов, стек пути, пометки ветвей или скрытую обучаемую память без изменения постановки пользователем.
- По D-0006 базовый вариант — A, а подсказки направлений B отклонены. Расположения сервисов известны; общий расчёт длин может знать всю сеть дорог, но сообщает длины только из текущей фактической позиции. Не возвращай B через запросы к воображаемым соседним позициям. По D-0007 в A подаётся вся накопленная память (C). Кодирование для табличной SARSA описано в [E-0001](docs/experiments/E-0001-sarsa.md).
- D сейчас обсуждается: поиск, выбирающий ход после решения о потребности, относится к аппарату принятия решений, а не к физической среде. При этом его готовые правила действительно ограничивают RL тремя решениями о потребности. Не объявляй D отклонённым или вновь выбранным без ответа пользователя.
- По [D-0009](docs/decisions/0009-sarsa-splits.md) исходные уровни 01–10 закреплены за test. Обучай SARSA на отдельных картах train от простых к сложным, отбирай модель на val всех сложностей. Результат однократного итогового test в E-0001 уже сохранён.
- Предложение ассистента и результат статьи не становятся требованием проекта автоматически. Помечай предложения; актуальное указание пользователя имеет приоритет над прежней записью в документах.
- Различай состояние симулятора, доступную агенту информацию и журналы оценки. Истинная карта и будущие события не должны попадать в контроллер неявно.

## Как завершать работу

Выполняй необходимые обратимые действия в рамках запроса без дополнительных согласований. Не расширяй исследовательскую постановку молча. Если существенный выбор действительно мешает реализации, сформулируй конкретный вопрос и продолжай независимую часть работы; список открытых вопросов сам по себе не запрещает работу.

Изменяй документы, чьи сведения затронуты. Существенное решение сопровождай причиной, статусом и источником; завершённый этап — проверяемым результатом. `status.md` обновляй при изменении этапа или следующего шага, `journal.md` — при содержательном событии, а не после каждой реплики.

Для изменений Markdown доступна проверка `python scripts/check_docs.py` из корня проекта. Она проверяет локальные ссылки, но не научную корректность. Команды запуска симулятора, обучения и проверок приведены в [README.md](README.md).

У корня проекта и `Articles/` отдельные репозитории Git. Перед действиями с Git проверь фактическую границу репозитория. Сохраняй существующую структуру при обычной правке документации.
