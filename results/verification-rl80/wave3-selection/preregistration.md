# Отбор одного кандидата третьей волны

Две новые учебные сотни, сида 9167001 и 9167002, каждая содержит по 25 карт H1–H4. До физических поездок отдельный процесс проверяет отпечатки стен при восьми ориентациях, взаимную непересекаемость сотен, E-0016, исходные и подтверждающие сотни. При построении исключений из защищённых файлов используются только зарегистрированные поля отпечатков. Оценщик и политики получают новые отборочные карты и наблюдения соответственно. В этом опыте нет поездок на прежних наборах.

| Метод | Кандидат | SHA-256 весов |
|---|---|---|
| A | service-window/fixed | eb11b8ec3f1c6c2f24996e23fe9384f91b3bba33cffa8202193109911cce6f4c |
| B | conservative/frozen, порог из регистрации 0,9 | f9bd509a7d4778f4d0e33cd1ad3924f8eb8a0923086c8448b42ac7ebddee35bf |
| C | tree-search/model | 839140fa1346c675d550f6ee4ace6aaa5eb9f7a1d07c254a2be8a6e86f6f0bed |
| D | panel-search/model | 07859179f66199b6ecf95c5ef662f3bde4ad31b5956aa7ef8ae568446d958576 |

У каждой карты четыре физические поездки с одинаковыми начальными запасами и штатным лимитом. Перед картой оба регистра пусты; процессы контроллеров изолированы от симулятора. Политика вызывается в обычном режиме по фактическому Observation, все команды передаются в Environment.step. Если штатный метод использует кэш, его ключ содержит всё наблюдение и оба прошлых показания. При любом решении оба регистра обновляются. Веса и порог фиксированы.

Победителя определяет максимальная меньшая из двух долей финишей, затем сумма финишей, затем суммарное число финишей H4, затем приоритет A, B, C, D. Обе сотни имеют одинаковый знаменатель 100. До раскрытия результатов определены фазовые показатели: раскрытие полных окон 3×3 вокруг F и R, первое привлечение поздней части, физическое приобретение обоих сервисов, успешное завершение после передачи и случаи отказа до неё. Сохраняются действия, их хеши, исходы и счётчики. Запуск исторической волны требует отдельного решения директора.
