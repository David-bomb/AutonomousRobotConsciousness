# Проверка исторического учителя на новом train

Проверяется единственная запись `mandatory-proof` из E-0010. Фабрика `bench.controller` разрешает эту запись в `maze.mandatory_supply.MandatoryProof`. Класс, все 41 импортированный им модуль `maze.*`, инициализатор пакета и таблица фабрик сверены со снимком `pause-mandatory-nov26.zip` после нормализации переводов строк. SHA-256 снимка — `6c74af7ca3034e02c798b2715c0e9e131d626b1c702509ddcc350fad67603d82`. Исходники среды и оценщика, версии Python, SciPy и NumPy также закреплены. [Регистрация до первого физического эпизода](lock.json)

## Карты и вычислительный бюджет

Используется файл `results/E-0016/sequence/train.jsonl` с SHA-256 `6affb0aa46384b2f3485e630524bb0dc02abb5b5f9901adee4f786b0d1ada763`. В срезе строк с индексами 700–799 при нумерации с нуля по 25 карт H1–H4. Пересчитаны геометрии всех 100 карт с учётом восьми ориентаций. Все 100 различны. Источник содержит исходные топливо и исправность. Отдельная проверка непересечения с закрытыми наборами входит в регистрацию производителя банка. Здесь проверен отпечаток train. [Регистрация банка](../../E-0016/sequence/bank.json)

Перед пробой записаны конкретные индексы для обеих предусмотренных продолжительностей. Первая карта каждого класса проходит оба режима. Если эти четыре пары вместе с запуском процессов и разбором отказов занимают более 75 секунд, берутся первые четыре карты каждого класса. Иначе берутся первые восемь. Проба входит в итог. Четыре параллельных задания работают на CPU, по одному потоку численных библиотек на контроллер. [Измерение пробы](physical/timing-rule.json)

## Что сохраняет автомат

**Полный режим.** Для каждой карты и режима создаётся отдельный процесс. В полном режиме в нём один штатный экземпляр `MandatoryProof` на эпизод. Автомат сохраняет режим, сведения о пробах направлений и другие предусмотренные историческим алгоритмом поля. Внутри эпизода работают штатные кэши. Этот режим показывает силу архивного дискретного учителя при его собственном объёме памяти.

**Два прежних показания.** Перед каждым решением очищаются все 55 обёрток `lru_cache` из импортированной цепочки `maze.*`, включая таблицы соседей и кэши, зависящие только от размеров. Затем конструируется новый `MandatoryProof()`. На старте его `_fallback.last_lengths` пуст. На последующих шагах в этот словарь записываются лишь `Mode.FUEL` и `Mode.REPAIR` со значениями из непосредственно предыдущего фактического `Observation`. Автомат получает текущий `Observation` и возвращает один ход. Только после выбора обёртка заменяет сразу оба регистра текущими показаниями. Отсутствующее показание остаётся `None`. При неудавшемся перемещении регистры обновляются тем же способом, а архивные методы сами проверяют `view.moved`. Штатные `last_move`, `moved`, текущая позиция и уже открытые клетки входят в текущее восприятие.

Экземпляры автомата, в том числе `_fallback.mode`, `returning`, `_unseen`, `_service_streak`, `standby`, `ready` и `offer`, создаются заново. Из предыдущего решения доступны только два показания. Последний результат вычислений может физически оставаться в кэше до начала следующего вызова. Очистка предшествует конструктору и чтению данных автоматом. Повторяющееся восприятие каждый раз приводит к вызову штатного `choose`. [Адаптер](adapter.py) · [Архивный класс](../../../maze/mandatory_supply.py)

При разборе исходников проверены глобальные переменные модулей, кэши методов, изменяемые значения аргументов по умолчанию и генераторы случайных чисел. Обнаруженные генераторы создаются из локально заданного начального значения. Таблицы предполагаемых дорожных сетей строятся самим контроллером из разрешённых входов и фиксированных правил. Отдельный синтетический тест заполняет кэш предыдущего хода, изменяет поля автомата и различает оба канала при совпадающем текущем снимке. Для штатного `choose` он также сверяет действия с прямым вызовом заново сконструированного автомата. [Самотест](selftest.py)

## Граница информации и начало отказа

Оценщик создаёт среду и получает исход каждого физического хода через `Environment.step`. Рабочий процесс получает при загрузке один из двух фиксированных режимов, далее в канале передаются только поля штатного `Observation`. Ни имя карты, ни класс, ни банк, ни симулятор в процесс контроллера не передаются. После загрузки адаптера ограничены открытие файлов данных, подключение сокетов и запуск подпроцессов. Граница опирается на аудит конкретных исходников и обычную изоляцию процессов. Хук Python сам по себе не защищает от произвольного недоверенного нативного кода и побочных каналов времени.

После терминального исхода внешний поиск по истинной карте проверяет, можно ли достичь финиша с данными запасами за оставшиеся ходы. Вдоль исполненного пути потеря возможности завершить поездку необратима. Для отказа двоичный поиск находит два соседних состояния по разные стороны этой границы. Для первого хода, после которого успех невозможен, дополнительно проверяются все разрешённые альтернативы. Поля `before` и `after` содержат позицию, топливо, исправность и накопленные числа заправок и ремонтов. `phase` указывает сервисы, уже посещённые до этого хода. Эти данные получает только внешний журнал. При успехе `first_loss` равен `null`. [Физический прогон и поиск](run.py)

## Воспроизведение

Команды для PowerShell из корня проекта используют системный Python 3.13.2, NumPy 2.4.4 и SciPy 1.17.1. Первая проверяет сброс регистров и кэшей. Вторая воспроизводит физику по сохранённым командам и пересчитывает результат и границы отказов. Третья запускает новые поездки в отдельную папку. На другой машине измеренное время пробы может выбрать другую предусмотренную численность.

```powershell
$dir = 'results/verification-rl80/mandatory-proof-train'
python -X utf8 -B "$dir/selftest.py"
python -X utf8 -B "$dir/verify.py"
python -X utf8 -B "$dir/run.py" run --out "$dir/repeat"
```
