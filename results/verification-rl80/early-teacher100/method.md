# Условия опыта и чтение ранних демонстраций

Банк и обе ветви зарегистрированы до первого измерения пары. SHA-256 файла регистрации — `fb2e1825d00c0383a5052d66288b337737e219c8525ec26cbac26459d3cc4ba0`. Сотня `phase100-train` содержит 100 разных геометрий. Совпадение набора между двумя ветвями проверяется по ID, отпечаткам стен, обоим начальным запасам и сложности. [Предрегистрация](preregistration.md) · [Зафиксированный код и веса](lock.json) · [Банк train](../phase100-train/train.jsonl)

Фиксированная смесь получает один штатный `Observation` на каждый такт. Ранние решения wave1 используют два показания из предыдущего фактического наблюдения. При повторном использовании ответа ключ содержит всё наблюдение и оба регистра, а после любого вызова регистры обновляются. Для ветви с учителем системный Python загружает тот же архивный адаптер, что и в парном испытании на 32 картах. Перед каждым ранним решением он очищает 55 кэшей, конструирует новый автомат и вводит только два прежних показания. Когда окна раскрылись, новый процесс проектного Python загружает исходный joint400 и вызывает `choose(view)` на каждом оставшемся шаге. В обоих режимах контроллеры изолированы от симулятора и получают только наблюдения. [Исполнитель поездок](run.py) · [Архивный адаптер](../mandatory-proof-train/adapter.py) · [Точки входа нейронных моделей](neural.py)

Момент раскрытия окон считается после физического хода. Если счётчик равен 12, то первые 12 команд гибридной ветви выбрал учитель, а на 13-м ходу решение принимает joint400, если поездка продолжается. Раскрытие окон определяется по фактически осмотренным клеткам вокруг меток F и R в памяти. Отдельная веха `first_both_services` учитывает физическую заправку и физический ремонт. Начальный остаток для анализа тесных запасов равен минимуму из двух разностей между внутренним запасом и показанием длины пути до соответствующего сервиса.

В каждом файле `episodes` сохранены полные траектории обеих ветвей, первый момент раскрытия окон, первый момент приобретения обоих сервисов, исход и счётчики. Хеш команд вычисляется по последовательности однобайтовых индексов N, E, S, W, NE, SE, SW, NW. В раннюю демонстрацию входят только первые `teacher_steps` команд ветви `hybrid`. Строки банка позволяют физически восстановить каждое входное наблюдение и предыдущие показания перед соответствующим действием.

Для проверки хеша меток `teacher_labels_sha256` по каждому шагу в SHA-256 последовательно добавляются три части. Первая — UTF-8 JSON всех полей `Observation` с отсортированными ключами, короткими разделителями и переводом LF, где `last_move` передан именем перечисления или `null`. Вторая — компактный JSON-массив прежних показаний F/R с переводом LF, на старте `[null,null]`. Третья — один сырой байт выбранного направления. Приёмник может сверить эти хеши до использования примеров. [Функции записи и вычисления хеша](run.py) · [Физическая сверка и подсчёт пар](verify.py)
