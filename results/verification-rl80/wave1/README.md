## Контроллер и физическая поездка

В отдельный каталог скопированы байты весов и все девять файлов из регистрации разработчика. Вызов `frozen_adapter.load` проходит по закреплённым копиям модулей. Проверены пути фактически импортированных файлов и загруженной `geometry.dll`. Все 12 тензоров контроллера `Policy` на CPU совпали с файлом весов. Выключены режим обучения и градиенты. Перед контролем отдельная поездка на dev с этими копиями воспроизвела исход, число ходов, заправок и ремонтов исходной записи. [Проверка цепочки](chain.json) · [Проверка поездки dev](independent/adapter-check.json)

На каждой карте создаются новый `Environment` и новый процесс контроллера. Выбор хода получает только штатное `Observation`. Контроллер берёт первое максимальное значение среди оценок восьми движений с учётом маски из текущего окна. Позиция, окно, внутренняя память клеток и запасы обновляются штатной средой. Оценщик исполняет каждый возвращённый ход одним вызовом `env.step`, в том числе при повторяющихся наблюдениях, до терминального исхода. Для каждой сотни выделен отдельный процесс контроллера в каждый момент времени. На одну карту приходится ровно одна поездка в официальной серии. [Исполнение и проверка](run.py) · [Спецификация исторических сотен](../stress-spec.json)

```powershell
$v = 'results/verification-rl80/wave1'
& $py -X utf8 -B "$v/check_chain.py"
& $py -X utf8 -B "$v/run.py" verify --lock-sha256 6d05dbc9dfe404c5c5960bec2c22a5ab603653a8000db3f6590edfb2c5801053
```
