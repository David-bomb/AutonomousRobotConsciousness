На всех 100 картах с первичным журналом совпали исход, число шагов, оба счётчика сервиса и SHA-256 последовательности действий. ## Подключение в Diplom

Из корня репозитория под Windows, в проектном окружении с Python 3.13.2, PyTorch 2.8.0 и NumPy 2.2.6. Для одной карты `level` типа `maze.levels.Level` вызов выглядит так.

```python
from importlib import import_module
from pathlib import Path
from maze.environment import Environment
from maze.runner import run

path = Path("results/verification-rl80/frontier48-dev/frozen/model.pt")
load = import_module("results.verification-rl80.frontier48-dev.bridge").load
outcome = run(Environment(level), load(path.read_bytes()))
```

Формат E-0016 предполагает две заправки, две ремонтные станции и доступные текущие показания расстояний. Для выбора сеть использует текущий снимок памяти клеток, штатное восприятие и внутренние показатели. В файл весов входят 35 тензоров базы `mission600/s8.pt` и вектор коэффициентов. Два активных значения, 12 и 8, участвуют в выборе по подтверждённому маршруту и по пути к границе разведанного участка. Модель хранит обученные параметры неизменными и вычисляет оценки на CPU. При равных максимальных оценках берётся первое направление в порядке N, E, S, W, NE, SE, SW, NW. [Проверка содержимого весов](deployment-check.json) · [Запись выбора параметров](decision.json)

Точка входа привязывает импорт исходного адаптера к локальной копии `sequence.model`. Его относительные импорты и обе нативные библиотеки также берутся из `frozen`. Все восемь файлов зависимостей, включая исходники C++, совпали по SHA-256 с ранее закреплёнными версиями для mission600. Прямой вызов на синтетическом уровне подтвердил загрузку из папки поставки и физическое исполнение команды. Для работы достаточно репозитория Diplom с указанными библиотеками. ## Порядок проверки

Каждая из 100 карт dev получает штатную начальную память, ресурсы, лимит и новый процесс контроллера. Оценщик передаёт процессу только `Observation`, запрашивает одно действие и вызывает `Environment.step` на каждом такте до терминального исхода. Исходный авторский прогон мог повторно использовать ответ для тождественного наблюдения. Независимый прогон вызывает политику заново на каждом физическом шаге. Геометрические кэши адаптера индексируются аргументами вычисления по доступному восприятию. Истинная карта, идентификатор, класс сложности, сид и журналы остаются у оценщика.

Покартовый SHA-256 в обоих журналах вычислен по последовательности **сырых байтов со значениями 0–7**, по одному на физическое действие в указанном порядке направлений. Например, пара «север, восток» кодируется двумя байтами `00 01` в шестнадцатеричной записи. При сверке по ID отдельно проверяются геометрия и класс, затем исход, число шагов, заправки, ремонты и хеш действий. [Первичный журнал](packed-dev.json) · [Сценарий сверки](check_dev.py)

Повторно проверить сохранённые журналы можно из корня проекта. Для новой физической поездки используется команда `run` с `--out` и новым путём.

```powershell
$dir = 'results/verification-rl80/frontier48-dev'
$hash = 'bf590732bf56eb60fd98665dfcd9bf20c59387c70d04138540bfa7c3627efded'
& .\venv\Scripts\python.exe -B -X utf8 "$dir/check_dev.py" verify --lock-sha256 $hash
```
