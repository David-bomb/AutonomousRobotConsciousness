# Независимая проверка контроллера с двумя предыдущими показаниями

Независимый оценщик поддерживает этот вариант без изменения `Observation` и физики. Сверх штатного наблюдения между решениями разрешены два регистра — предыдущее фактическое показание длины пути до ближайшей заправки F и до ближайшей мастерской R. Обычная `mission600/rl` проходит отдельную проверку в исходном интерфейсе. [Согласование варианта](../../E-0016/prev-two/protocol.md) · [Независимый оценщик](../evaluate.py)

## Один физический ход

1. Перед первым решением оба регистра имеют значение `None`. Оценщик запускает новый процесс и создаёт новый контроллер для каждой карты. Если внешний вызывающий код повторно использует экземпляр, перед стартом нужно вызвать `reset()` одновременно со сбросом среды.
2. На такте `t` оценщик передаёт только `env.view` из фактической позиции. Внешний метод контроллера — `choose(view) -> Move`. Внутренняя функция выбора получает `decide(view, previous_fuel, previous_repair)` и может сопоставить прежние показания с `view.fuel_distance` и `view.repair_distance`. На старте доступны только текущие показания.
3. После выбора одного хода контроллер записывает в оба регистра значения `view.fuel_distance` и `view.repair_distance` этого же такта. Нулевая длина на станции сохраняется как `0`. Отсутствующее показание сохраняется как `None`, в том числе если отсутствует только один из двух сервисов.
4. Оценщик исполняет ровно один `env.step(move)`. Следующее решение получает новое фактическое наблюдение и пару, сохранённую до исполнения хода. Столкновение тоже расходует физический шаг. Оба регистра обновляются в обычном порядке и при неизменной позиции. После терминального исхода вызовы прекращаются.

В предоставленной обёртке постоянная функция выбора и два регистра — все поля экземпляра. Новые числа поступают только из полученного `Observation`. Внешнее состояние оценщика, включая маршрут и журнал диагностики, политике недоступно через этот интерфейс. Для будущего кандидата проверке подлежат также исходники самой функции выбора, замыкания и модули модели, поскольку одна сигнатура не ограничивает состояние произвольной программы. [Обёртка двух регистров](controller.py) · [Обмен с процессом контроллера](../policy_worker.py)

Независимый прогон вызывает политику при каждом физическом шаге. Для версии с двумя регистрами нельзя использовать без изменений прежний код dev, который сохраняет выбранный ход по одному `Observation` и при повторе пропускает вызов контроллера. Если ускоряют внутренний расчёт фиксированных весов, его ключ должен включать `(view, previous_fuel, previous_repair)`. Даже при попадании в кеш внешний `choose` записывает **оба** текущих показания перед возвратом. Кеш вычислений привязывают к весам и режиму оценки. Штатная память клеток, лимит и порядок разрешения ничьей сохраняются. [Цикл независимого физического прогона](../evaluate.py)

## Проверка на искусственных картах

На четырёх маленьких картах робот из старта делает шаг на восток. Верхний и нижний удалённые проходы независимо меняют длины пути до F и R на старте. Во второй позиции тест проверяет точное равенство **всего** объекта `Observation` на четырёх картах, включая память клеток, окно, запасы и предыдущий ход. Все текущие длины равны `(3, 3)`. Фиктивная политика различает четыре пары предшествующих реальных измерений.

| Предыдущее F | Предыдущее R | Второй ход |
|---:|---:|---|
| 3 | 3 | Восток |
| 4 | 3 | Север |
| 3 | 4 | Юг |
| 4 | 4 | Запад |

В отдельном цикле между соседними F и R встретились четыре различных полных наблюдения, одно из них — 71 раз. Через настоящий процесс контроллера прошли 144 вызова функции выбора и 144 физических хода до штатного лимита. На каждом такте внешний тест сопоставил входы функции выбора с наблюдениями до двух последовательных физических ходов. Отдельно проверены столкновение, недоступный ремонт, нулевая длина на F, начальная пустая пара и явный сброс между эпизодами. Диагностическая запись искусственной политики идёт в одном направлении через stderr и не участвует в выборе хода. [Синтетический самотест](selftest.py) · [Сохранённый результат](selftest.json)

Команда из корня проекта повторяет проверки на 159 физических ходах и сверяет результат с сохранённым.

```powershell
& .\venv\Scripts\python.exe -X utf8 -B results/verification-rl80/previous_readings/selftest.py
```

Для подачи будущего кандидата используется прежняя фабрика `load(checkpoint: bytes)`. Она возвращает новый контроллер с `choose(view)`, например `PreviousReadings(decide)`. Его веса, входная фабрика и зависимости закрепляются отдельно от обычной модели. Самотест подтверждает передачу допустимых входов и своевременное обновление регистров. Качество обученного кандидата требуется измерить на его собственных поездках.
