# E-0016. Гипотеза комнат при выборе физического хода

При возобновлении сохранились исходные снимки прежних учебных поездок и поэпизодные исходы field3000-clean и field3200. Извлечение признаков комнат, обучение их весов и проверка полных поездок ещё не выполнялись. Снимки предварительно разделены по геометриям. На каждой из 3 000 геометрий обучения взято до восьми ранних наблюдений, на каждой из 200 геометрий вспомогательной проверки — до двенадцати. Дорожная обстановка и остатки ресурсов получены в физическом симуляторе. Эти 200 карт также использовались для выбора ранее обученной сети, оценивающей выходы с известной дороги. Для проверки всей системы выделена ещё одна полностью новая учебная сотня. [Исходные снимки](../early.json) · [Извлечение и состав данных](data.json)

В семействе «комнаты» видимая дорога на клетке с обеими чётными координатами указывает на покрывающий её квадрат 3×3. Гипотеза проверяет совместимость квадратов с наблюдавшимися стенами. Дополнительные признаки описывают число возможных комнат, открытые стены и расположение сервисов. Частоты числа комнат для размеров карты оценены только по первым 3 000 учебным геометриям. Сеть оценивает вероятность семейства по одному снимку и для каждого разрешённого хода сопоставляет два представления доступной дороги. Гипотетические клетки существуют только во временном расчёте. Память клеток агента заполняет штатная физика. Истинное семейство и скрытые стены используются при обучении и внешнем измерении точности. [Признаки](cells.py) · [Аппарат выбора из восьми движений](model.py)

Классификатор семейства прошёл 800 обновлений, модель действий — 1 200. У неё три выхода для каждого хода: сокращение показания до срочного сервиса, сохранение достижимости финиша и принадлежность кратчайшему успешному продолжению. Последнее размечено на учебных геометриях. На каждом четвёртом обновлении поданы две копии исходной памяти. Это позволяет измерить вклад геометрической гипотезы при одних весах. На отдельных учебных состояниях сообщаются точность распознавания семьи, число жизнеспособных выборов на критических развилках и результат по H4. Единица измерения при проверке восстановленных клеток — пара «клетка и текущее наблюдение». [Обучение](fit.py) · [Измерения по состояниям](held.json)

Выход для физического хода обучается по терминальному SUCCESS. На 40 учебных стартах сравниваются 17 наборов коэффициентов при неизменных весах внутренних сетей. Четыре лучших ненулевых варианта, заранее заданный выход до этого этапа и базовая политика сравниваются на следующих 200 стартах. Приоритет — число финишей, затем результат на самой слабой сложности. Для проверки гипотезы публикуется лучший вариант с наблюдаемым изменением хотя бы одной поездки. Исходная политика участвует в том же сравнении и сохраняет своё место при лучшем результате. Веса и их SHA-256 записываются перед полным dev. [Регистрация 200 карт](bank.json) · [Варианты и критерий](../../runs/rooms3000/config.json) · [Штатные прогоны](physical.py)

Ещё 100 новых учебных геометрий с seed 9164502 предназначены только для проверки замороженной поправки. Базовый и новый контроллер проходят каждую карту до штатного терминала. Внешний наблюдатель разбирает первую развилку при запасе ≤2 и первый необратимый ход базовой политики за первые 150 ходов до посещения обоих сервисов. Веса фиксируются до этого сравнения. Каждое физическое перемещение вызывает `Environment.step`. Пороги на dev и отдельных новых стартах помогают координатору выбрать момент передачи. Пользовательское условие — ≥80/100 на каждой из трёх исходных сотен. [Код отдельной проверки](independent.py)

Для повтора замороженного кандидата из корня Diplom используется команда ниже. Она сравнивает все сто поэпизодных записей dev и запускает первый эпизод через изолированный процесс оценщика.

```powershell
& .\venv\Scripts\python.exe -B -m results.E-0016.sequence.publish_next results/E-0016/sequence/runs/rooms3000/rl.pt rooms
```

Для повторной сборки парного отчёта из сохранённых физических поездок используется следующая команда. Она проверяет соответствие весов, состав dev и совпадение имён карт в парах.

```powershell
& .\venv\Scripts\python.exe -B -m results.E-0016.sequence.spatial.rooms.compare
```
