# Восстановление двух показаний по текущему снимку

Регистрируем опыт до сбора примеров. Замороженные ранняя wave1 и поздняя joint400 берутся из комплекта wave1-joint400. Переход к поздней сети определяется раскрытыми окнами F и R в памяти. Политика получает один обычный Observation. Предыдущее показание на каждом из двух датчиков восстанавливается как нынешнее минус предполагаемое изменение. У совместного изменения девять классов. На старте оба предыдущих показания пусты.

Для предварительного обучения геометрического прогноза используем ходы обратно к предыдущей клетке из существующих физических префиксов **extra[:3000]**. Для отдельного сбора последовательных фактических показаний заранее закрепляем **large[7000:7400]** для обучения, **[7400:7500]** для вспомогательной проверки и **[7500:7600]** для отбора по полным физическим финишам. В каждой сотне поровну H1–H4. Эти карты прошли прежнюю регистрацию по каноническим отпечаткам стен. В более раннем опыте они использовались для другой сети LocalNet. Её веса в данном опыте не используются. Основной dev — ранее зарегистрированная открытая сотня той же серии.

Сохраняем реальные пары до и после последнего физического хода только при сборе train, отдельно отмечаем старт. В модели измерения используются текущие показатели, направление последнего хода, память и известные координаты станций. На доступной дороге обратный ход к предыдущей клетке даёт нижнюю и верхнюю границы возможной длины. Вычисление применяет эти границы к вероятностям классов. На вспомогательной сотне проверяем девять на девять ошибок распознавания, отдельно для состояний, где разные допустимые пары меняют предпочтение ранней сети, а также согласие выбранного действия и сохранение достижимости.

Три варианта проходят каждый физический старт. Первый подаёт отсутствующую пару в wave1. Второй усредняет восемь выходов wave1 по предсказанному распределению допустимых пар. Третий обучает прямые восемь оценок действий по примерам чувствительных решений. Исходный выход при пустой паре доступен всем. На train допускается разметка чувствительности по реальным значениям, достижимости по учебной карте и исполнение случайного разрешённого действия для покрытия отклонений. В качестве проверки переноса сравниваются полные финиши трёх способов.

Отбор варианта и силы поправки — по числу SUCCESS на ста отдельных учебных стартах, затем по слабейшей сложности, при равенстве — по порядку регистрации. Проверяем все три способа на dev только после сохранения весов, способа и SHA-256. Исполняем каждый ход штатным Environment.step. Цель окончательного исследования остаётся ≥80/100 на каждой исходной сотне.
