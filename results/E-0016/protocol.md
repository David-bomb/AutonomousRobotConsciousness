# E-0016. Обучение прямому выбору хода

27.11.2026. Цель пользователя — одни веса с минимум 80 физическими финишами на каждой из трёх прежних сотен. Координатор проводит итоговую проверку отдельно. Граница политики закреплена до обучения: текущий Observation, включая всю разрешённую память типов клеток, два штатных показания длин из фактической позиции, известные позиции сервисов и цели. Сеть выдаёт восемь оценок, в полной поездке берётся разрешённый максимум. Нет обращения к будущему наблюдению, генератору или полной карте, хранения истории решений или накопления градиентов на проверке.

## Новый банк и допуск к проверке

Независимые зёрна архивного генератора и разделение по рисунку стен закреплены до извлечения учебных состояний. Из каждой сотни по 25 карт H1–H4 с исходной смесью четырёх семейств. Первые восемь сотен — train, следующая — dev для разработки, две другие — однократное подтверждение на новых картах. Все эти рисунки исключают дубли в восьми ориентациях внутри и между выборками, архивы трёх сотен, контроль E-0012 и прежние исключения генератора. Подробности и отпечатки в [манифесте](data/manifest.json). Доказательные маршруты и разметка оставшихся ходов доступны обучению исключительно на train. Оценка на dev начинается с исходных запасов и чистой памяти, продолжается до SUCCESS, EMPTY, BROKEN или LIMIT. Отдельно сохраняются заезды обоих типов.

Вес фиксируется файлом и SHA-256 до прохода на dev. Для пилота сравниваем одни и те же 100 карт до подражания, после подражания и после обучения по награде. Кандидатов ранжируем по числу финишей на dev, затем по минимуму финишей среди четырёх уровней сложности, при равенстве берём более раннюю запись. Для допуска к двум новым подтверждающим сотням заранее требуем ≥85/100 на dev, ≥18/25 на каждой сложности и повторяемость выгруженных весов. Перед подтверждением замораживаем один кандидат, код и хеши. Требуем ≥80 на каждой новой сотне. Только затем передаём эти же веса на I/II/III. Уже раскрытые три сотни годятся для проверки прикладной цели на фиксированных картах. Независимый вывод о переносе требует новых геометрий. Число финишей обученных и случайной сетей, доля обоих сервисов, причина остановки и распределение по сложности считаются по полным поездкам.

## Первый запуск

Уточнение координатора до первых оценок пилота. Пороги dev и двух подтверждающих сотен служат основанием для передачи весов. При исчерпании бюджета волны координатор получает лучший доступный чекпойнт после RL по тому же правилу ранжирования, его хеш, адаптер и измеренное качество, даже если пороги ещё не достигнуты. Только одна самостоятельная модель с ≥80/100 на каждой исходной сотне выполняет цель пользователя. Начальные и учительские веса служат контрольными точками для измерения вклада обучения. Факторное сравнение R×C выполняет независимый чат на CPU в папке `factorial/`.

Сначала 200 новых учебных геометрий (два полных блока), 100 dev, одно зерно 1601. Учитель с полной картой формирует короткие физически выполнимые маршруты и помечает несколько равных ходов, если они есть. Общий для восьми направлений обучаемый слой читает числовые признаки и геометрию каждого направления по памяти. Сравниваем случайные веса, подражание и обновление политическим градиентом по собственным поездкам. При малом числе финишей проверить самостоятельно посещённые состояния и повторные проходы. Следующая допустимая попытка — добавить их разметку на train, расширить число независимых геометрий, затем повторить RL и проверить полный dev. Финальное условие остаётся прикладным, а порог 85 — предварительным допуском.

## Продолжение после двух пилотов

Физическая перепроверка дала 20/100 и 28/100 для первых двух моделей после RL. На 81 потере финиша первого пилота на первой учебной сотне 42 произошли до первого заезда, 19 после обоих сервисов. На этом основании в третьей попытке сеть на train перехватывается перед необратимым ходом. Наблюдатель точно проверяет все восемь физических вариантов на выделенных критических развилках. При обновлении параметров к 192 обычным состояниям добавляются 64 критических, дополнительная выходная величина учится предсказывать сохранение возможности финиша. Далее — 12 групп по 32 самостоятельно сыгранных эпизода, политический градиент по терминальному 1 за SUCCESS и 0 за другие исходы, γ=1. Оба изменения оцениваются совместно. Валидация всегда исполняет каждый ход через Environment.step.

До получения результатов третьей попытки зафиксирована четвёртая. Оставить тот же банк из 800 train, построить на нём простую таблицу частот проходимости клетки по чётности координат, признаку края и доступным четырём соседям. Хранить таблицу в самих весах. Предъявить сети дополнительные геометрические признаки по ещё одной возможной достройке её собственной памяти, сохранив исходные признаки и маску движений из фактического окна. Передать лучшие по официальной dev веса после RL, получить новую разметку на train, затем выполнить две заранее заданные фазы по восемь групп терминального RL. Сохранить обе контрольные точки, выбрать кандидата по прежнему правилу. Ориентир волны — четыре обучения с полным dev после этапов; после четвёртого передать лучший полученный RL-чекпойнт координатору. Для заявления о 80/100 требуются три фактических результата итогового оценщика.

## Отдельное сравнение награды и порядка задач

Для изоляции факторов предлагаются четыре ветви Double DQN v03 на одном банке E-0012. R0 — штатная награда E-0015, R1 — новая формула из [численного теста](reward_test.py). C0 — штатные три ступени по размеру. C1 — три ступени по длине и потребности, сначала короткие поездки с достаточными запасами, затем с одним обязательным обслуживанием, в конце с двумя. Для воспроизведения C1 ранжировать сценарии по паре (число начальных запасов меньше прямой длины, прямая длина), разрезать отсортированный список на три равные части с порядком по имени при равенстве. Использовать тот же алгоритм колоды с десятью задачами прошлых ступеней. Физический старт сохраняется целиком. У распределения фактически начатых поездок и числа успехов ожидаются различия, их нужно публиковать по ветвям. Это сравнение прежней и новой программы выдачи, включая её состав в ограниченном бюджете.

Один технический квартет на зерне 39139, по 24 среды × 256 ходов × 3 ступени = 18 432 взаимодействия и 384 обновления на ветвь. При конечных обновлениях, совпадении исходных весов, отсутствии пересечений и точном бюджете повторить пятизёренный опыт по 73 728 ходов, 1 536 обновлений на ветвь. Во всех ячейках оставить γ=0,97, Adam, архитектуру, расписание исследования, буфер и синхронизацию E-0015. Отличия R1−R0 сравнивать при обоих порядках, C1−C0 при обеих наградах, отдельно разность этих парных эффектов по зерну. Сохранять долю финишей и посещение сервисов на общих val от реального старта, по ступеням и дефицитам, пары полученных/утраченных финишей. Интервалы по картам строить с кластеризацией по геометрии, разброс между зёрнами показывать отдельно. Увеличение γ проверять другим опытом. Приоритет по уточнению пользователя — обученный пилот на новом банке с учителем и последующим RL. Результат пилота следует интерпретировать отдельно от причинного сравнения четырёх ветвей.
