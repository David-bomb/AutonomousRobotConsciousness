# Предварительная регистрация независимой ветви E-0016

Источник условий — [общий протокол](../protocol.md), раздел об отдельном сравнении, и пять конфигураций обычной CNN из E-0015. Четыре модели заново инициализируются на каждом зерне. Последние веса каждой модели замораживаются до валидации. Выбора лучшей модели или ранней остановки по качеству нет.

| Фактор | 0 | 1 |
|---|---|---|
| R, награда обучения | Штатная функция E-0015 | Шаг −0,12, финиш +8, иная остановка −8, разность потенциалов по reward_test.shaped |
| C, порядок выдачи | Исходное деление по размеру, исходный порядок записей до перемешивания | Все 120 000 сценариев сортируются по числу запасов ниже прямой длины, прямой длине и имени. Три последовательные группы по 40 000, внутри групп сохраняется этот порядок перед штатным перемешиванием |

Длина берётся из зарегистрированной записи генератора о кратчайшем пути от старта к цели. Начальные запасы и все сервисы остаются штатными. У C1 граница трети может пересекать категорию потребности. Текущая ступень использует прежнюю колоду и десять случайных задач прошлых ступеней. Разница C включает состав фактически выданных задач.

Вначале технический квартет на 39139, 24 среды × 256 ходов × 3 ступени, по 384 обновления. После проверки конечности обновлений, равных начальных весов в квартете, точного бюджета и раздельности train/dev — пять квартетов по 1024 хода на среду на ступени и 1536 обновлений на модель. Зёрна 39139, 71809, 92221, 130031, 175003. Техническое зерно повторяется в полной серии, технические результаты в неё не входят. Вычисляем прогноз длительности полной серии как 20 длительностей технического квартета (пять квартетов вчетверо длиннее). При прогнозе до двух часов продолжаем все пять. Выбор сделан до измерения скорости. Один процесс с максимум двумя вычислительными потоками, только CPU.

## Измерения

- Один и тот же dev E-0012/E-0015 — validation_id, геометрии с индексами 0–59, четыре сценария на геометрию. Это прежний диагностический dev. Целевая величина — доля физических SUCCESS в 240 обычных полных поездках. Одна поездка стартует с исходной позиции, запасов и штатной памяти. Замороженная CNN принимает только encode(Observation, False) и выбирает разрешённый максимум. Симулятор проводит каждый ход до штатного конца. Эталонные сотни и новый confirmation закрыты для ветви.
- На каждой карте сохраняем физический исход, ходы, заправки, ремонты, посещение каждого и обоих сервисов, дисконтированный возврат с γ=0,97 одновременно по R0 и R1. Среднее R1−R0 на одних траекториях измеряет смену шкалы. Сравнение моделей по одному фиксированному возврату измеряет изменение траекторий. Оба показателя вторичны к финишам.
- По каждому зерну сравним R1−R0 при C0 и C1, C1−C0 при R0 и R1, а также взаимодействие (R1C1−R0C1)−(R1C0−R0C0). Для каждой простой пары сохраняем полученные и утраченные финиши по именам. Для всех ячеек публикуем результаты по размерной ступени и начальному дефициту (топливо/исправность ниже прямой длины), а по учебным ступеням — реально начатые, завершённые и успешные поездки с распределением по входным сценариям.
- Основное обобщение — равновзвешенное среднее парных разностей по пяти зёрнам. 95%-интервал по картам — процентили 2,5 и 97,5 при 20 000 перевыборок 60 геометрий с возвращением, зерно 160016. В каждой геометрии вместе остаются четыре сценария и все ветви и зёрна. Разброс между обучениями показываем отдельно по парным эффектам каждого зерна, выборочному стандартному отклонению и ориентировочному t-интервалу среднего при пяти зёрнах. Эти интервалы условны по второй оси, технический квартет даёт только картовый интервал. Отбор по результатам и поправка на множественность не предусмотрены.
- До обучения фиксируем отпечатки кода, источников, списков train/dev, групп, стартовых весов и версий. Для каждой ветви проверяем устройство, конечность, изменение весов, число ходов и обновлений, соответствие хеша при загрузке, статус завершения всех сценариев и тождество терминального телескопического возврата R1. Отдельно сверяем результат с обычным архивным оценщиком.
