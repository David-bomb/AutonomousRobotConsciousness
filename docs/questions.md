# Открытые вопросы и принятые решения

Номера Q сохраняются, когда вопрос переходит из обсуждения в реализацию. Для сравнительного опыта с RL остаются следующие выборы.

| ID | Открытый вопрос | Что уже известно |
|---|---|---|
| Q-002 | Сравнивать ли варианты со счётчиком посещений и как считать посещение? | В пилоте хранятся только типы клеток. Дополнительный счётчик допускается [D-0002](decisions/0002-spatial-memory.md). |
| Q-012 | Как оценивать успешность, длину пути и бесполезные повторы? | Метрики, число повторов и разделение карт фиксируются до итогового сравнения. [Протокол](experiments/README.md) |
| Q-014 | Нужен ли отдельный вариант D? | Базовым остаётся A. В D заранее заданный поиск внутри аппарата ограничивает обучаемый выбор тремя потребностями. [Разбор](concepts/memory-and-decision-boundary.md) |
| Q-016 | Как поощрять обслуживание, чтобы повторный круг между сервисами не давал выигрыша за всю поездку? | В E-0015 сравнили круги и успешные продолжения из одинаковых позиций. Изменение сервисного слагаемого предложено для отдельного опыта. [Действующая формула](../results/E-0015/reward-diagnosis.md#награда-за-один-ход) · [Проверка и предложение](../results/E-0015/reward-diagnosis.md#что-проверить-при-изменении-награды) |

## Что определено для пилота

| ID | Вопрос | Рабочее решение и основание |
|---|---|---|
| Q-001 | Как используется карта в таблице? | В E-0001 оценки ходов объединены по признакам продвижения на карте памяти и риска для запасов. [Кодирование](experiments/E-0001-sarsa.md) |
| Q-006 | Какую награду назначать? | В E-0001 заданы штраф за ход, терминальный исход и сигналы продвижения и ресурсов. [Формула и изменения](experiments/E-0001-sarsa.md) |
| Q-007 | Какой алгоритм и бюджет? | SARSA(0), выбор с вероятностью исследования, 3720 эпизодов на попытку. [Обучение](experiments/E-0001-sarsa.md) |
| Q-003 | Как задать сервисы и их число? | Все позиции заранее отмечены F и R на карте памяти. Состав объектов задаёт файл уровня. [Уровни](../maze/levels) |
| Q-004 | Какую длину передавать до сервиса? | По одному минимуму из фактической клетки для каждого типа, при отсутствии достижимого сервиса — `None`. [Интерфейс](architecture.md#вход-аппарата-принятия-решений) |
| Q-005 | Как устроены наблюдение, локализация и движение? | Статическая сетка, точная позиция и окно 3×3 постоянной ориентации. Ход в любом из восьми направлений имеет длину 1. Диагональ требует двух свободных боковых клеток. [Шаг среды](architecture.md#порядок-шага) |
| Q-008 | Как задан финиш? | Смещения со знаком `dx` и `dy` передаются на каждом шаге. [D-0007](decisions/0007-agent-map-and-service-distances.md) |
| Q-011 | Какой стек у прототипа? | Python, текстовые уровни и отдельное окно Tk. [Запуск](../README.md) |
| Q-013 | Кому доступна полная сеть дорог? | Среде для расчёта двух длин. Контроллер ищет путь по своей памяти. [D-0006](decisions/0006-baseline-a-and-rejected-b.md) |
| Q-015 | Когда проверять перенос? | Отбор на смешанной val, один итоговый test после прохождения порога. [D-0009](decisions/0009-sarsa-splits.md) |
