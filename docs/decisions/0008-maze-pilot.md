# D-0008. Рабочий пилот навигационного автомата

24.11.2026. Реализовано по запросу на алгоритмического робота, уровни возрастающей сложности и отдельный визуальный запуск. Правила ниже выбраны для воспроизводимых диагностических прогонов. При подготовке сравнения с RL их можно пересмотреть явно. Вариант A и состав входа сохраняются. [D-0007](0007-agent-map-and-service-distances.md)

## Основания и схема работы

Работы Core связывают восприятие, собственное состояние, действие и отчёт об исполнении. Проект MicroMouse показывает, как робот обновляет карту стен и пересчитывает пути. У Ямаути робот достигает границы изученной области и расширяет карту следующим наблюдением. В пилоте использованы эти принципы. Три режима потребностей, правило запаса четырёх ходов и схема расхода разработаны для этой задачи. [Конспект Core](../../Articles/Core/main_ideas.md) · [MicroMouse, Floodfill Solving Algorithm](https://justinsapun.com/pages/sub_engs/micromouse.html) · [Yamauchi, 1997](https://doi.org/10.1109/CIRA.1997.613851)

1. Среда хранит статическую карту уровня. При создании она один раз вычисляет два поля длин поиском в ширину от всех объектов соответствующего типа. На вход выдаются только два значения для фактической клетки. Отсутствующий или недостижимый сервис обозначается `None`.
2. Перед каждым решением память записывает типы из окна 3×3 относительно точного положения робота. Ось x направлена вправо, y вниз. Наблюдаются все девять клеток, за краем видна стена. Положения F и R заранее отмечены на карте известного размера, будущие наблюдения скрыты. Снимки памяти неизменяемы.
3. Аппарат получает снимок, окно, позицию, Dx/Dy, две длины, топливо, исправность и результат предыдущей команды. Метод `choose(view)` возвращает один из восьми ходов. Режим потребности и поиск направления принадлежат автомату. Табличный RL сможет выбрать направление по тому же входу.
4. В физике пилота одна попытка хода расходует по единице топлива и исправности. Длина каждого разрешённого хода равна 1. Для диагонали обе боковые клетки должны быть проходимы. При столкновении позиция сохраняется. По въезде на F или R соответствующий показатель восстанавливается до 100. Затем проверяются финиш, нулевое топливо, нулевая исправность и лимит в таком порядке. Последней единицы хватает на въезд на финиш или соответствующий сервис. По умолчанию лимит равен восьми площадям карты в клетках. Награда для RL остаётся открытым выбором.

## Переходы автомата

Начальный режим — движение к B. В начале каждого решения поиск в ширину от текущей позиции по **известным проходимым клеткам** даёт длины и первые ходы. Для полностью известного пути к финишу, на который хватает обоих ресурсов, приоритет получает B.

Для каждой потребности автомат вычитает из остатка ресурса сообщённую длину пути до сервиса. При остатке после вычитания от 0 до 4 включительно возникает потребность. Ранее выбранная потребность сохраняет право на выбор и при большем запасе, пока сервис достижим на соответствующем ресурсе. Если актуальны две потребности, выбирается меньший запас, при равенстве первой рассматривается заправка. Нулевая длина означает, что робот уже на сервисе. Если актуальных потребностей нет, он продолжает к B.

Для выбранного типа цели автомат ищет кратчайший полностью известный и посильный путь и исполняет его первый ход. Если такой путь пока неизвестен, рассматривает достижимые клетки, из которых откроется хотя бы одна новая клетка. Он минимизирует сумму длины известного пути и нижней оценки остатка до цели по восьми направлениям. При равенстве предпочитает меньший остаток, затем меньшие y и x. Так робот может вернуться от тупика и продолжить за пределами текущего окна. Временные результаты поиска исчезают после выбора команды. Между ходами автомат сохраняет только один из трёх режимов, а память клеток сохраняет только типы.

Это эвристика выбора потребности при частичном знании. На новой карте возможны поздний заезд, повторное движение или исчерпание ресурса. Если доступная область полностью исследована и посильного пути нет, физический интерфейс по-прежнему требует хода. Автомат выбирает первый доступный, а в изолированной клетке пробует север. Среда завершает эпизод по ресурсу или лимиту.

## Реализация и проверка

Python 3.12+ поддерживает используемые объявления типов. Проверено на Python 3.13.2 с Tk 8.6.15. Поиск использует `collections.deque`, интерфейс контроллера — `typing.Protocol`, тесты — `unittest`. Графический модуль загружается только с флагом `--visual`. Оба режима исполняют один шаг через `advance`. Для нового контроллера достаточно метода `choose`, экземпляр передаётся в `run`, фабрика — в `show`. Можно напрямую вызывать `env.reset()` и `env.step(move)` в обучающем цикле. Причина завершения доступна через `env.status`.

| Уровень | Задача | Ходов до B | Заправок / ремонтов |
|---|---|---:|---:|
| 01 | Пройти открытый участок с диагональю | 4 | 0 / 0 |
| 02 | Обойти стену слева или справа | 9 | 0 / 0 |
| 03 | Вернуться из тупика и найти обход | 30 | 0 / 0 |
| 04 | Выбрать заправку при запасе 8. Из A длины равны 26 и 6 | 18 | 1 / 0 |
| 05 | Свернуть к мастерской при начальной исправности 8 | 18 | 0 / 1 |
| 06 | Заправиться и позже заехать в мастерскую в длинном лабиринте | 44 | 1 / 1 |

Результаты получены командой `python -m maze` на шести фиксированных инженерных уровнях. Стартовые запасы и размещение сервисов входят в условия каждого уровня. Это диагностические карты разработки. Для сравнительного исследования понадобятся отдельно зафиксированные условия оценки. Парный тест на уровне 02 подводит робота в одну клетку после двух зеркальных поездок. Все поля наблюдения кроме памяти совпадают. По знакомому левому проходу аппарат выбирает запад, по правому — восток.

## Дополнительные уровни 07–10

Каждая заправка и мастерская расположена в конце бокового проезда с одним въездом. Чтобы продолжить путь к B, робот должен вернуться из проезда. Все дороги и станции достижимы из A. На каждой карте проведены два запуска одного автомата из A с пустой начальной памятью дорог и известными позициями сервисов. Меняются только начальные ресурсы.

Во всех четырёх запусках с начальными запасами 100 / 100 робот доехал до B с нулём заездов. На уровнях 09 и 10 также проверено независимое изменение одного ресурса. При заполнении только бака робот заезжает лишь в мастерскую, при восстановлении только исправности — лишь на заправку. Каждый заезд в этих проверках выполнен в режиме соответствующей потребности.

**Выбор между двумя заправками на уровне 07.** После 24 ходов робот стоит в клетке (6, 6). Его карта памяти уже содержит оба маршрута. До заправки (4, 3) по прямой около 3,6 клетки, по дороге 23 хода. До заправки (11, 5) по прямой около 5,1 клетки, по дороге 6 ходов. На входе длина до ближайшей заправки равна 6. При остатке топлива 10 автомат выбирает восток и через шесть ходов заправляется в (11, 5). В запуске с полным начальным баком к этому моменту осталось 76 единиц топлива. Все остальные поля наблюдения совпадают, и робот выбирает запад к финишу. Полная карта использована в проверке как эталон длин. [Регрессионные тесты](../../tests/test_service_choices.py)

Для наблюдения за моментом выбора запустите `python -m maze --visual --level 07-locks`. Начало координат находится в левом верхнем углу с индексами (0, 0).
