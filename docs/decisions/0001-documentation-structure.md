# D-0001. Структура документации

- Дата: 24.09.2026.
- Статус: принято в рамках порученной организации документации.
- Основание: пользователь попросил создать `docs`, изучить интернет-рекомендации и подготовить структуру для долгой работы.

## Контекст

До этого исследовательские идеи и проектные предложения находились в `Articles/main_ideas.md`, корневой `DOCS.md` был пуст. Длительная работа требует сохранять текущие требования, причины выбора, нерешённые вопросы и проверяемый прогресс вне одного диалога.

## Решение

Сохранить библиотеку в `Articles`. Создать короткий `AGENTS.md` как маршрут к тематическим документам, а `docs` использовать для текущей постановки, архитектуры, вопросов, решений, этапов и опытов. Пустой `DOCS.md` заполнить указателем. Шаблоны применять только при соответствующей задаче.

Требования ведутся в `project.md`, научный синтез — в `Articles/main_ideas.md`. У них разные роли; перекрёстные ссылки заменяют независимые копии спецификации. Проверять локальные ссылки переносимым скриптом стандартной библиотеки Python.

## Альтернативы

Один большой документ проще создать, но в нём смешиваются источники, планы и обязательства. Обязательное чтение всех документов перед каждой правкой расходует контекст независимо от задачи. Большое число пустых разделов создаёт навигацию без содержания.

## Последствия и проверка

Новая задача может восстановить состояние по короткому статусу и профильным ссылкам. Содержательные изменения требуют обновления соответствующей записи. Создание документов не выбирает RL, интерфейс или правила среды.

Проверка: существование основных документов, локальные ссылки и ручная сверка статусов с указаниями пользователя. Интернет-основания и их ограничения: [documentation-sources.md](../documentation-sources.md).
