# D-0004. Полная сеть дорог, два уровня помощи и две ветви выбора сервиса

- Дата: 24.09.2026.
- Статус: частично заменено [D-0006](0006-baseline-a-and-rejected-b.md) 04.10.2026. Полная сеть дорог для расчёта длин сохраняется; B отклонён, A выбран базовым. Ниже сохранено основание прежнего решения.
- Связано с: REQ-003–REQ-005, REQ-008, REQ-011–REQ-013, Q-004, Q-013, Q-014.
- Реализация: отсутствует; разрабатываются концепты.

## Основание

На вопрос о доступных дорогах пользователь выбрал: «Полная сеть дорог доступна общему модулю навигации; датчик робота остаётся 3×3».

На вопрос о жёстком выборе ближайшего сервиса или обучаемом поведении пользователь выбрал: «Разработать оба подхода отдельно».

На вопрос о длинах путей до объектов или дополнительной подсказке следующего хода пользователь выбрал: «Рассмотреть оба уровня помощи как отдельные варианты».

## Решение

Общий для автомата и RL навигатор может использовать полную сеть дорог. Его выходы входят в явно описанный информационный интерфейс. Это разрешённое предварительное знание; оно не означает, что датчик видит всю карту или что накопленная память заполняется истинными типами всех клеток.

Разрабатываются две самостоятельные ветви:

1. Аппарат принятия решений сам выбирает движение и учитывает длины путей. Ошибки выбора сервиса остаются возможны и измеряются.
2. Ближайший сервис выбранного типа и движение к нему определяет общий навигатор по жёсткому правилу. Следует отдельно описать, какие решения остаются автомату и RL.

Для самостоятельного выбора направления отдельно сохраняются оба уровня помощи: длины путей до объектов и сведения, подсказывающие следующий ход. Конкретная форма второго уровня — одно рекомендуемое направление или длины путей через каждый из восьми первых ходов — ещё не выбрана.

Это решение **не выбирает** окончательный формат входа, алгоритм RL, правила движения, счётчики или абстрактные действия. Замена восьми действий RL на три потребности была вынесена на отдельный выбор и впоследствии принята для жёсткой ветви в [D-0005](0005-controller-actions-and-first-pilot.md). Обе запрошенные ветви сохраняются в сравнении; одна не объявляется принятой вместо другой.

## Последствия

При неизменных дорогах и определённом правиле измерения длины навигатор может сравнивать кратчайшие разрешённые пути до сервисов. В примерах предлагается считать количество ходов. Близости по координатам для этого недостаточно. Равный учёт прямого и диагонального хода ещё не утверждён.

Полная сеть дорог позволяет точно рассчитывать кратчайшие пути. Она не гарантирует, что RL последует подсказке, и не решает автоматически выбор между заправкой, ремонтом и B с учётом топлива и исправности.

Сильная общая навигация может сделать пространственную память избыточной для выбора маршрута. Это допустимый результат сравнения, который следует измерить, а не скрывать дополнительными усложнениями среды.

## Проверка будущей реализации

- Оба контроллера получают одинаковые выходы навигатора в соответствующем варианте.
- Полная сеть дорог передаётся только по задокументированному каналу.
- Накопленная карта содержит только разрешённые поля и сведения из предусмотренных источников.
- На карте с обходом препятствия ранжирование по длине пути отличается от ранжирования по координатам и совпадает с эталонным поиском.
- Гарантии относятся к тому модулю, который действительно ограничивает выбор действия.

Подробные варианты и замечания критика: [концепты симуляции](../concepts/simulation-options.md).

Редакционное уточнение 04.10.2026: по просьбе пользователя вместо «стоимости» используется «длина пути». Система цен или отдельный внутренний показатель этим решением не вводились; принятые пользователем варианты сохранены.
