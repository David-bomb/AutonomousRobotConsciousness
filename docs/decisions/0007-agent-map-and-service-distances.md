# D-0007. Карта памяти, смещение до цели и длины путей до сервисов

24.11.2026. Принято по уточнению пользователя о входе агента. Уточняет [D-0006](0006-baseline-a-and-rejected-b.md) для первого опыта и сохраняет состав памяти по [D-0002](0002-spatial-memory.md) и известность сервисов по [D-0003](0003-known-services.md). Состояние реализации — спецификация.

## Решение

На каждом шаге дискретный автомат и RL получают всю карту, которую построил агент своего запуска к моменту решения. Агент обновляет её из текущего восприятия 3×3. Для точки назначения B передаются два смещения со знаком: `Dx = x_B − x_t` и `Dy = y_B − y_t`. Для сервисов передаются два числа: длина кратчайшего разрешённого пути до ближайшей заправки и такая же длина до ближайшей мастерской. Каждый минимум вычисляется отдельно по полной сети дорог из фактической текущей клетки. Аппарат принятия решений выбирает одно из восьми направлений.

Эти величины отвечают на разные вопросы. Смещение показывает положение B относительно агента. Длина пути учитывает обходы и может быть большой даже у сервиса, расположенного рядом за стеной. Карта сохраняет наблюдавшиеся клетки, в том числе вышедшие за пределы текущего окна. Формат известного положения сервисов на карте, отметка текущей клетки и обозначение отсутствующего пути предложены в [архитектуре](../architecture.md). Включение счётчика посещений, длина диагонального хода и способ использования карты табличным RL остаются открытыми.

## Основание в литературе

В инженерном проекте MicroMouse датчики сообщают о стенах, робот обновляет карту, и алгоритм движения заново вычисляет длины по известным проходам. У Geng и соавторов локальные измерения пополняют карту свободных и занятых участков. По этой карте планировщик формирует промежуточные цели для RL. Для проекта принят общий принцип обновления и чтения отдельной карты. Конкретные четыре навигационные величины задал пользователь. [Sapun и др., MicroMouse, раздел Floodfill Solving Algorithm](https://justinsapun.com/pages/sub_engs/micromouse.html) · [Geng и др., IROS 2026, с. 3–4 PDF](https://rasevents.org/uploads/documents/pdfviewer/03/d8/236366-1470.pdf)

## Как проверить интерфейс

- Клетка, которая была видна раньше и теперь находится вне окна 3×3, сохраняет известный тип. Участок дороги, который агент ещё не видел, остаётся неизвестным даже при доступной длине пути до сервиса за ним.
- При смене стороны относительно B меняется знак соответствующего смещения. При достижении B оба смещения равны нулю.
- В [примере с двумя заправками](../concepts/simulation-critique.md) при длинах 18 и 7 на вход поступает 7, а после открытия прохода в другой конфигурации при длинах 6 и 7 поступает 6. Положение заправок в двух конфигурациях совпадает. Минимум для мастерских вычисляется независимо.
- Для проверки использования памяти можно подать контроллеру две совместимые с разными историями наблюдения карты при одинаковых текущем окне, показателях и навигационных величинах. Взять развилку, где ранее замеченная преграда за пределами окна даёт основание выбрать другой ход.
