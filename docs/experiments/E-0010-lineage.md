# E-0010. Дерево попыток навигационного автомата

Цель эксперимента — один детерминированный автомат с результатом не ниже 85/100 **на каждой** из трёх стресс-сотен и 36/36 на val. Единица наблюдения — самостоятельная поездка на карте с исходными ресурсами и лимитом ходов. Корень дерева — закреплённый `frontier-reserve`. [Решение D-0010](../decisions/0010-frontier-reserve.md)

Текущий срез на паузе — [сводка 177 полных серий](E-0010-results.md). Ниже сохранены основания изменений, отрицательные результаты и прежние контрольные точки. Статус запущенных и неполных серий в каждой датированной записи относится к моменту этой записи.

## Протокол

Сотни I, II и III взяты соответственно из исходного стресс-набора, проверки E-0007 и проверки E-0009. Все четыре выборки служат для разработки в этом цикле. При повторном использовании результат на них измеряет достижение заданной цели. Для вывода о переносе потребуется новый независимый набор. Исходные десять карт итоговой проверки SARSA в стенд не входят. [Состав и порядок запуска](../../results/E-0010/bench.py)

Контроллер получает штатный `Observation`. Длины до сервисов измеряются из фактической клетки. Типы неизвестных клеток остаются в памяти неизвестными. Оценки возможных продолжений вычисляются заново по этой памяти. Контроллеру недоступны имя карты, семейство, номер набора, оптимальный путь, траектории других поездок и истинная геометрия. Ресурсы и правила движения общие для всех версий.

Каждая ветвь проходит одинаковые 336 карт. Журнал содержит исход, число ходов, заправок, ремонтов и всю последовательность физических команд. Цифры 0–7 соответствуют порядку `Move` в интерфейсе. В отдельном сравнении с родителем сохраняются приобретения, потери, изменения числа ходов, первая различающаяся команда и первый ход после которого финиш уже физически невозможен. При оценке необратимости учитывается оставшийся лимит. Истинная карта доступна внешнему проверяющему после эпизода. [Интерфейс](../../maze/interface.py) · [Парное сравнение](../../results/E-0010/compare.py)

При перечислении спасающих направлений проверяющий рассматривает разрешённые переходы в соседние клетки. Столкновение со стеной не входит в список таких направлений. В воспроизведении записанных команд действуют исходные правила симулятора, включая расход обоих ресурсов при столкновении.

Из корня проекта первый вызов продолжает серию с отсутствующих карт. Второй сравнивает два полных журнала. Третий строит сводку из готовых серий и существующих парных сравнений. Для ограничения ЦП на Windows используются psutil и pywin32.

```powershell
python -B -X utf8 results/E-0010/cpu_limited.py room-passages
python -B -X utf8 results/E-0010/cpu_limited.py --run results/E-0010/compare.py room-passages room-reserve
python -B -X utf8 results/E-0010/cpu_limited.py --run results/E-0010/ledger.py
python -B -X utf8 results/E-0010/cpu_limited.py --run -m maze --controller street-trunk-reserve --split val --level val-3-10
```

Для гипотез о дорогах в этой серии использованы NumPy 2.4.4 и SciPy 1.17.1. Для воспроизведения записи по карте последовательность команд берётся из журнала соответствующего агента. Для запуска его штатной визуализации на val к последней команде можно добавить `--visual`. Парное сравнение требует двух завершённых серий. Промежуточные записи хранятся в файле `.partial`, повторный вызов продолжает с недостающих карт. Аргумент `--compare-missing` у `ledger.py` выполняет сравнения последовательно в том же процессе.

Для продолжения всей очереди используется `python -B -X utf8 results/E-0010/cpu_limited.py --queue results/E-0010/cpu-queue.json`. Родственные контроллеры могут по очереди выполнять по одному ходу на общей для сравнения карте. У каждого свои экземпляры среды, аппарата принятия решений и памяти. Между ходами переиспользуются результаты функций от одинаковых входных данных. Завершённые поездки сразу записываются по одной в журнал соответствующего контроллера. На H1-05, val-1-01 и val-3-10 у `street-trunk` и `street-trunk-reserve` все шесть таких поездок совпали с ранее выполненными раздельными запусками по каждой команде, исходу и счётчикам. В ограниченном режиме прошли все 37 тестов проекта. [Очередь](../../results/E-0010/cpu-queue.json) · [Физический прогон и сверка](../../results/E-0010/grouped_runs.py)

После ускорения поиска по неизменившейся карте памяти во всех 120 проверках совпали порядок обхода, длины и первые ходы для 7979 посещённых позиций. В шести сверочных поездках также совпали все команды роботов. Затем под ограничителем прошли 39 тестов проекта. [Проверка поиска](../../results/E-0010/grid-audit.json)
