# Повтор экспериментов dot на исходном проекте

25.11.2026. Цель повтора — проверить результаты из [переданной сводки](../../results/ARC-dot/source/ARC-dot-experiments-handoff.md) по отдельным картам, воспроизвести диагностику отказов и заполнить пропуски стресс-теста. В [папке исходных материалов](../../results/ARC-dot/source/) находятся четыре архива и их распакованное содержимое. [Журналы повтора](../../results/ARC-dot/replay/) хранятся отдельно.

## Условия

База стендов — коммит `df9ba049d7a53a41990127a857d4b57efcb4ff5c`. Для каждого опыта использованы исходники соответствующей версии из патча. В стресс-тесте базовая среда, пилот, ресурсный автомат, его версия r1 и замороженная SARSA взяты из проекта. Для сверки текстовых исходников на Windows переводы строк приводились к LF. Сумма SHA-256 таблицы SARSA начинается с `677eb3af`. [Версии и контрольные суммы](../../results/ARC-dot/replay/provenance.json)

Каждый эпизод начинался с новой среды и контроллера. Архивные уровни 01–10 проверялись здесь на воспроизводимость ранее известных результатов. Полная карта использовалась внешним диагностом для поиска последнего состояния, из которого ещё можно добраться до финиша. Решение контроллера воспроизводилось по его обычному наблюдению.

## Стресс-тест на 100 картах другой геометрии

Запускались 16 контроллеров на каждой из 100 карт. Архивный файл карт имеет SHA-256 `ea09b467f486a64ffcabe20086c632da27c9c431e55d017be2732174971ef899`. Повторная генерация с зерном 20318577 и исходным списком исключений воспроизвела содержимое всех строк. В каждой группе сложности 25 карт. Во всём наборе по 25 карт четырёх семейств. Медиана наименьшего стартового запаса сверх длины пути к сервису по группам — 7, 5, 3 и 1. Внешний поиск по исходной физике проверил для каждой карты, что указанной оптимальной длины достаточно, а на один ход меньше — уже нет. Начальное значение каждого из двух ресурсов меньше длины самого короткого пути к финишу, поэтому необходимы и заправка, и ремонт. ## Что удалось сверить с архивом

Для всех 36 стресс-карт без единого финиша дополнительно исполнены кратчайшие маршруты и определён первый необратимый ход frontier-reserve. [Разбор по картам и предложения для автомата](ARC-dot-unsolved.md)

Совпали 1 344 строки эпизодов и 336 записей об отказах E-0004, 200 строк и 18 записей об отказах контрольной сотни E-0005. На разработке E-0005 совпали все доступные агрегаты итоговой настройки по пяти наборам, включая общее число ходов. В E-0006 совпали исход и число ходов для 2 016 пар «вариант × карта» разработки, все 300 строк отдельной сотни и 35 записей об отказах. В совокупности основные журналы повтора содержат 5 796 записей об эпизодах, включая стресс-тест. ## Как воспроизвести проверку

Для каждого стенда нужна отдельная копия базового коммита. В копии E-0004 применяется `frontier.patch` из [первого пакета](../../results/ARC-dot/source/ARC-frontier-experiment/), в E-0005 — `full.patch` из [второго](../../results/ARC-dot/source/ARC-frontier-reserve/), в E-0006 — `full.patch` из [третьего](../../results/ARC-dot/source/ARC-frontier-auto/). У каждого патча одна и та же исходная база. В командах ниже обозначения в угловых скобках заменяются путями. Для новых прогонов нужны свободные выходные пути.

| Рабочая папка | Команда |
|---|---|
| Стенд E-0004 | `python -m scripts.evaluate_frontier <новая-папка-E4>` |
| Стенд E-0005 | `python -m scripts.compare_frontier_reserve <новая-папка-E5>` |
| Стенд E-0006 | `python -m scripts.iterate_frontier <новая-папка-E6> --split fresh --agents C reserve frontier` |
| Стенд E-0006 | `python -m unittest discover -s tests` |
| Корень проекта | `python results/ARC-dot/run_development.py <стенд-E5> <новый.csv> e5` |
| Корень проекта | `python results/ARC-dot/run_development.py <стенд-E6> <новый.csv> <набор>`, по одному разу для `train`, `val`, `test`, `holdout`, `reserve-fresh` |
| Корень проекта | `python results/ARC-dot/source/ARC-stress-100/run_benchmark.py <стенд-E6> results/ARC-dot/source/ARC-stress-100/maps.jsonl <новая-папка-стресса>` |
| Корень проекта | `python results/ARC-dot/diagnose_replay.py <стенд-E5> <журнал-E4/diagnosis.json> <журнал-E5/diagnosis.json> <новый.json>` |
| Корень проекта | `python results/ARC-dot/compare_replay.py` для сверки сохранённых журналов |

Архив E-0004 содержит исходник итоговой политики. Для промежуточных реализаций, которым приписаны 23/36, 27/36 и 35/36 на val, сохранён только текстовый результат. В E-0005 для промежуточных настроек есть таблица разработки без отдельных снимков исходников. Их показатели остаются результатами автора сводки. Варианты A–F E-0006 доступны в исходном коде.
