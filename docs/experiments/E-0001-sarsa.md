# E-0001. Обучение SARSA на отдельных картах

## План до запуска

По указанию пользователя все десять существующих карт закреплены за test. В этом опыте обучение сразу проверяет перенос между картами. Создаём 90 новых карт train и 36 новых карт val, поровну в трёх группах сложности. Для обучения и валидации используются разные зерна генератора. Проверяем отсутствие совпадающей геометрии, включая повороты и отражения, с обеими другими выборками. Разметка сложности и полная карта доступны составителю выборок.

1. Сначала обучать на простых картах, затем добавлять средние и сложные. При повышении сложности повторять часть предыдущих карт. Обновлять Q только на train.
2. Выполнить оценку четырёх снимков таблицы на val в последней стадии. Каждую карту проходить один раз с фиксированным разрешением равенства и выключенным исследованием. Выбрать снимок по худшей доле успеха среди трёх групп, затем по общему числу успехов, затем по средней длине успешного эпизода. При полном равенстве сохранить более ранний снимок.
3. **Допуск к test** требует не менее 80% успеха на всех 36 картах val (минимум 29) и не менее 75% на каждом уровне сложности (минимум 9 из 12). При недостижении порога работать только с train и val. Сохранять результаты попыток.
4. Зафиксировать выбранную таблицу и контрольную сумму. Один раз провести её по всем десяти картам test в исходных условиях. Сохранить исход, число ходов, заправок и ремонтов для каждой карты, включая провалы. После вскрытия test параметры по его результатам не подбирать.

Вопрос опыта — какую долю ранее не встречавшихся карт проходит жадная политика одного обученного контроллера. Единица оценки — карта с заданным стартом и ресурсами. Повтор детерминированного проезда не добавляет независимого наблюдения. Сравнение нескольких случайных инициализаций обучения выходит за рамки этого запуска.

Начальный план обучения: зерно 39139, 12/24/48 эпох по ступеням, за эпоху все 30 карт текущей сложности и по 10 случайных с каждой предыдущей. На каждой ступени вероятность случайного допустимого хода линейно убывает с 0,24 до 0,04. Снимки для val — эпохи 12, 24, 36 и 48 третьей ступени. Шаг обучения 0,12, дисконтирование 0,97. Награда за шаг −1, дополнительно +40 за финиш или −40 за другой конец эпизода. Добавка за изменение потенциала равна 0,97 Φ′ − Φ, где Φ = −0,65 × оценка длины до B по памяти + 0,06 × (топливо + исправность). В терминальном состоянии Φ′ = 0.

## Обучение и отбор до открытия test

Карты сохранены в [train](../../maze/datasets/train.jsonl) и [val](../../maze/datasets/val.jsonl). Зёрна генератора 21701 и 83497. На первой ступени размер стороны 7–11 клеток, ресурсы полные. На второй стороне соответствует 11–17 клеток, начальный запас одного ресурса меньше длины кратчайшего пути до B. На третьей размер стороны 17–27, оба ресурса требуют обслуживания. При построении средних и сложных карт сервисы размещаются вне кратчайших путей от A до B. Генератор подбирает достижимый порядок обслуживания при заданных запасах. [Генератор](../../scripts/make_sarsa_maps.py)

У первой версии лучший снимок прошёл 23/36 карт, включая 3/12 сложных. Допуска к test не было. На train при двух дефицитах наблюдались поздние заезды и движение к сервису, после которого второй запас уже иссякал. [Отчёт первой попытки](../../results/E-0001/run-01/training.json)

Для второй попытки сохранили карты, бюджет, зерно и порог. Шаг обучения снизили до 0,025. Таблица объединяет симметричные случаи топлива и исправности. На основании памяти контроллер вычисляет для B и сервисов возможные кратчайшие пути через неизвестные клетки и подтверждённые пути через известные клетки. Для B используется известный путь, если он есть. Для сервиса известное направление выделяется, когда длина подтверждённого пути совпадает с показанием датчика. Остальные оценки сервиса опираются на возможные пути.

Если известного пути до B хватает на оба запаса, признаков дефицита нет. Иначе ресурс считается под угрозой, когда сервис достижим по показанию датчика, агент находится вне него и запас не превышает расчётный бюджет или превышает длину до сервиса максимум на 14. Бюджет равен известной длине до B, а для ещё неизвестной дороги равен удвоенной оптимистической длине плюс 9. Ресурсы под угрозой упорядочиваются по запасу, затем по длине до сервиса. Для каждого физически допустимого хода таблица получает число таких ресурсов и три бита: уменьшает ли ход оценку длины до B, первого и второго сервиса. Ходы с одинаковым ключом делят оценку Q. Инициализация нулевая. При равенстве оценок берётся первое допустимое направление в порядке перечисления Move. Правила выделения признаков заданы разработчиком, значения Q выучены на train. [Контроллер](../../maze/sarsa.py)

Дополнительный обучающий сигнал второй попытки равен уменьшению показания датчика сервиса между двумя фактическими позициями с весом 3 для первого дефицита и 1 для второго. При отсутствии дефицита добавка нулевая. Агент выбирает следующее исследовательское действие до обновления. Используется цель SARSA (r + γ Q(s′,a′)), при завершении — только (r). Во время оценки таблица заморожена.

## Воспроизведение

Python 3.13.2, стандартная библиотека. Вторая попытка заняла около 36 секунд. Для воспроизведения обучения и четырёх оценок val в свободной папке:

```powershell
python -m maze.learning train --run tmp/sarsa-reproduction
```

Для итогового запуска использована команда `python -m maze.learning test --run results/E-0001/run-02`. После регистрации результата повторный вызов с этой моделью сообщает о сохранённой оценке. Просмотр на val доступен через `python -m maze.learning watch`. [Команды и проверка допуска](../../maze/learning.py)
