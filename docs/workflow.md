# Порядок работы и сопровождения документации

Статус: рабочий процесс проекта, 24.09.2026. Источники общих рекомендаций и границы их применения перечислены в [documentation-sources.md](documentation-sources.md).

## Продолжение работы

Если контекст утрачен или задача новая, прочитать текущий статус и найти предметный документ по [навигации](README.md). Не загружать автоматически все статьи и планы. Перед изменением поведения сверить требования и относящиеся к нему решения; для правки опечатки это не требует полного обзора архитектуры.

Далее определить конкретный результат задачи и достаточную проверку. Небольшую правку выполнить непосредственно. Для работы на несколько сессий использовать план в `tasks/`: результат, ограничения, этапы, проверка и точка продолжения. Отдельный план не нужен для каждого ответа пользователю.

## Что обновлять

| Событие | Документы |
|---|---|
| Пользователь уточнил требование | `project.md`; относящийся вопрос; существенная причина/замена — в `decisions/` |
| Выбран формат или граница модуля | `architecture.md` и соответствующее решение |
| Изменился текущий этап или следующий шаг | `status.md`; существенное событие кратко в `journal.md` |
| Добавлена статья | Конспект папки, `Articles/README.md`, реестр источников; общий синтез при появлении общей идеи |
| Проведён эксперимент | Запись опыта с конфигурацией, командами, результатами и ограничениями |
| Появилась проверенная команда запуска | Этот документ или профильный документ; из статуса дать ссылку |

В одной задаче обновлять затронутые записи согласованно. Не переписывать все документы ради изменения даты. Сведения о прошедших этапах сохранять в журнале/плане; `status.md` оставлять коротким снимком настоящего.

## Решения и неопределённость

Предложение становится принятым, когда есть понятное основание: явное указание пользователя либо инженерный выбор в пределах порученной задачи. Если выбор меняет научную постановку, не выдавать своё предпочтение за согласие пользователя. Уже разрешённые действия не требуют повторного согласования из-за наличия шаблона или списка вопросов.

У решения хранить контекст, выбор, альтернативы, последствия и основание. При пересмотре создать новую запись и связать её с заменённой; историю причин не стирать. Открытый вопрос может быть разрешён и без отдельного решения, если изменение мало и не влияет на существенные допущения.

## Работа с научными сведениями

Разделять: результат первоисточника, нашу интерпретацию, предложение для проекта и проверенный собственный результат. Ссылка на статью не является подтверждением работоспособности нашей реализации. Указывать версию и страницы; математические гарантии переносить только с их предпосылками.

PDF не редактировать. Для литературы сохранять происхождение файлов и честный статус отсутствующих копий. Библиографические поправки и изменения требований не должны зависеть от памяти текущего диалога.

## Доступные команды

Из корня проекта, в PowerShell:

```powershell
python --version
python scripts/check_docs.py
```

Проверяющая утилита использует только стандартную библиотеку Python 3. Она просматривает корневые точки входа, Markdown внутри `docs` и `Articles`, пропуская Git-метаданные. Проверяет UTF-8, наличие непустого текста и существование целей локальных встроенных Markdown-ссылок. Возвращает ненулевой код при ошибке.

Она **не проверяет** доступность сайтов, якоря внутри документов, смысл утверждений или соответствие текста реализации. Эти части проверяются по задаче. При правке описания поведения сверять его с кодом или запуском соответствующего сценария.

Команды запуска автомата, просмотра и обучения приведены в [инструкции запуска](../README.md). Порядок допуска SARSA к отложенной выборке зафиксирован в [E-0001](experiments/E-0001-sarsa.md).

## Контроль версий

Из корня проекта проверяйте изменения кода и документации командой `git status`. У папки `Articles/` своя история Git. Чтобы увидеть изменения отдельных статей, используйте `git -C Articles status`.

## Критерий завершения задачи

Результат существует и соответствует запросу; подтверждённые ограничения сохранены; существенные допущения названы; относящаяся к изменению проверка выполнена либо точно указано, почему не выполнена; следующий шаг отражён, если он изменился. Планы, намерения и пустые шаблоны не объявляются реализованными алгоритмами.
