# Как табличный RL читает карту на развилке

24.11.2026. Предложение для первого опыта и отдельный числовой пример. Пользователь рассматривает SARSA. Требования к входу заданы в [D-0007](../decisions/0007-agent-map-and-service-distances.md). Выбор алгоритма остаётся открытым.

## Как найти строку таблицы

Карта `M_t` хранит известные агенту типы клеток в текущем эпизоде. Таблица `Q` хранит усвоенные за время обучения оценки действий. После обновления карты робот составляет ключ, по нему находит строку из восьми оценок и выбирает направление. Чем выше оценка, тем больше ожидаемая суммарная награда при таком ходе и последующем поведении агента.

Для маленькой фиксированной карты предлагается точное представление. Клетки `M_t` перечисляются по строкам в постоянной системе координат. «Неизвестно» имеет собственный код. Снимок неизменяем: наблюдение на следующем ходу образует новый ключ, если содержание карты изменилось. Одинаковые снимки получают один ключ независимо от порядка обнаружения клеток. Возможная запись состояния:

```text
s = (окно_3×3, топливо, исправность, результат_хода,
     Dx, Dy, L_fuel, L_repair, код_карты)
Q[s] = восемь оценок направлений
```

На фиксированной карте с одной фиксированной B пара `Dx, Dy` однозначно задаёт положение, а длины до сервисов определены этим положением. Повторно хранить их в ключе при таком доказуемом совпадении необязательно. Для табличного опыта значения ресурсов должны принимать конечное число значений. Если понадобятся интервалы, их границы предстоит проверить на ситуациях, где остатка ресурса как раз хватает или уже не хватает.

Достаточно создавать строки по мере появления состояний. Даже на одной статичной карте для `k` клеток существует до `2^k` наборов «тип уже известен / пока неизвестен». Это верхняя граница, геометрия и окно ограничивают достижимые наборы. Разные записи могут редко повторяться. При необходимости сокращения ключа можно отдельно испытать признаки, вычисляемые из карты, например типы на двух удалённых участках дороги. Для приведённого ниже случая достаточно двух таких клеток. На других развилках препятствия могут располагаться в других местах. Сокращение ключа требует самостоятельной проверки, поскольку оно объединяет ситуации. Способ чтения карты не должен давать контроллеру сведения из скрытой геометрии или предписывать следующий ход.

## Две истории в одном мире

На схеме решётка обозначает стену, точка — дорогу, B — цель, F — заправку, R — мастерскую. Верхняя строка имеет меньшую координату y. В окне 3×3 текущая клетка агента находится в центре. Там, где дорога расходится, в окне и в памяти у клетки тот же тип «дорога».

```text
#########
#...B...#
#.#####.#
#.......#
####.####
####F####
####R####
#########
```

Оба пробных прохода начинаются на дороге в двух клетках над заправкой. В первом агент исследует левый коридор до клетки перед B, во втором — правый. Каждый раз он возвращается тем же путём, спускается на одну клетку и снова подходит снизу к исходной позиции. Обе истории имеют одинаковую длину. В момент выбора агент видит `### / ... / #.#`. В обеих ситуациях `Dx = 0`, `Dy = −2`, до заправки 2 единичных хода, до мастерской 3. Запас топлива равен 30, исправность — 100, результат последнего хода — «выполнен».

В первой истории на карте остался весь проход в обход стены слева. Вертикальный проход справа ещё неизвестен. Во второй истории известен обход справа, а вертикальный проход слева ещё неизвестен. Пройти можно по обеим сторонам. На одном фиксированном поле проверяется способность таблицы учитывать опыт текущего эпизода. Обе дороги в этом примере равноценны по длине.

## Числовая проверка SARSA(0)

Для каждой из двух записей памяти задали восемь одинаковых продолжений по знакомому коридору. Каждое состоит из восьми прямых ходов до B. Остальные направления также имеют свои столбцы. В примере начальные оценки равны нулю, награда за вход в B равна 1, остальные награды равны 0, коэффициент обучения `α = 1`, коэффициент дисконтирования `γ = 0,9`. Обновления выполнялись по ходу каждого прохода. У последнего хода целевая оценка равна награде. За восемь повторов оценка первого хода из соответствующей строки таблицы достигает `0,9^7 = 0,4782969`.

| Строка в таблице | Q влево | Q вправо | Выбор наибольшей оценки |
|---|---:|---:|---|
| Известен левый проход | 0,4783 | 0 | Влево |
| Известен правый проход | 0 | 0,4783 | Вправо |
| Если убрать карту из ключа, общая строка по тем же проходам | 0,4783 | 0,4783 | Равенство в обеих историях |

Числа проверены отдельным расчётом обновлений по заданным проходам. Ноль в первых двух строках — начальная оценка действия без наблюдавшегося продолжения из этой строки. Правило равенства или случайный выбор может дать разные ходы и в третьей строке, но их распределение будет одним и тем же для обеих историй. Результат показывает, что таблица способна выразить зависимость от памяти. Для проверки пользы памяти при самостоятельном обучении потребуются исследование обоих ходов, одинаковая награда и одинаковый бюджет обучения в сравниваемых вариантах, а затем оценка при фиксированных параметрах. На одной постоянной карте агент может выучить удачный ход по положению даже с пустой памятью.

## Какой алгоритм применить

**Предложение — табличный SARSA(0)** с выбором по ε-жадному правилу. На обучении с вероятностью ε исследуется случайное направление, в остальных случаях выбирается одно из направлений с наибольшей оценкой. Сначала выполняется ход a и получается награда r. После обновления карты составляется следующая строка s′ и из неё тем же правилом выбирается фактический следующий ход a′. Обновление имеет вид:

```text
Q(s,a) ← Q(s,a) + α · [r + γ · Q(s′,a′) − Q(s,a)]
```

Если эпизод завершился достижением цели или иным терминальным исходом, будущая часть равна нулю. Так SARSA учитывает последствия того, как агент в действительности движется во время обучения, включая исследовательские ходы. Это существенно, если лишний ход может исчерпать топливо. [Sutton и Barto, главы 5–6](https://mitpress.ublish.com/book/reinforcement-learning-an-introduction-2)

| Метод | Что оценивает и как подходит к задаче |
|---|---|
| Q-learning | Тоже таблично оценивает восемь действий. Использует для обновления наибольшую следующую оценку. Ближайший способ сравнения с SARSA при том же ключе, награде и правилах исследования. [Watkins и Dayan](https://doi.org/10.1007/BF00992698) |
| TD, обучение по временным разностям | Семейство обновлений по полученной награде и текущей оценке продолжения. SARSA и Q-learning относятся к TD-управлению. Обычный TD(0) для ценности состояния оценивает заданное поведение. [Sutton и Barto, гл. 6](https://mitpress.ublish.com/book/reinforcement-learning-an-introduction-2) |
| Прямая оценка полезности и Монте-Карло | Усреднение суммарных наград после посещения состояния оценивает заданное поведение. Для выбора хода подходит табличное управление методом Монте-Карло с оценками пар «состояние, действие» и исследованием. Обновление ждёт завершения эпизода. [Sutton и Barto, гл. 5](https://mitpress.ublish.com/book/reinforcement-learning-an-introduction-2) |
| ADP, адаптивное динамическое программирование | По опыту оценивает модель переходов и наград, затем использует её для расчёта ценностей. Для управления требуется также выбирать или улучшать действия. Табличная модель добавляет вычисления и параметры для пар состояний с разными картами. Доступ модели к истинной карте дал бы ей сведения сверх интерфейса. [Russell и Norvig, пассивный и активный ADP](https://aima.cs.berkeley.edu/lisp/doc/overview-LEARNING.html) |
| REINFORCE | По отдаче эпизода изменяет параметры вероятностей действий. Можно задать восемь табличных предпочтений для каждой строки. Оценка градиента по целым проходам может сильно колебаться, особенно при редкой награде. [Williams](https://doi.org/10.1007/BF00992696) |
| PEGASUS | Сравнивает параметризованные правила поведения в симуляторе на общих наборах начальных условий и случайных чисел. Подходит для отдельного опыта по поиску параметров правил при наличии управляемого симулятора. [Ng и Jordan](https://arxiv.org/abs/1301.3878) |

Для первого сравнения автомат и SARSA получают [одни и те же сведения](../architecture.md). Чтобы выяснить вклад памяти, уместно отдельно сравнить SARSA с картой и SARSA без карты в ключе. Чтобы выяснить вклад метода обновления, следует сохранить карту в ключе у обоих алгоритмов и сравнить SARSA с Q-learning.
